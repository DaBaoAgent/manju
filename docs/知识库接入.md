## 工具：scripts/kb_files.py

只用标准库，PD 无依赖；token 从环境变量读。

```powershell
$py = 'C:\Users\Administrator\AppData\Local\Programs\Python\Python312\python.exe'

# 1) 找素材：列目录（-r 递归，--depth 限深）
& $py -X utf8 scripts\kb_files.py list --root archive --path "10 产品高清图/白底图" -r --depth 2

# 2) 先干跑看清单，再真下（中文名要带 --mirror-root）
& $py -X utf8 scripts\kb_files.py pull --root archive `
    --path "10 产品高清图/白底图/朋友2-绿-带扶手" `
    --dest "assets/refs/jks/助行器朋友2/白底图-带扶手" `
    --mirror-root "D:\BaiduSyncdisk" -r --include "*.png"

# 3) 单个文件
& $py -X utf8 scripts\kb_files.py get --root archive --path "10 产品高清图/P11.jpg" --dest assets/refs/jks
```

- `pull` 会在 `--dest` 下写 `_manifest.json`（来源路径 / `via` / 字节数 / sha256 / 时间），
  size 与 sha256 都匹配时重跑会跳过 —— 天然增量。
- `--max-bytes` 挡超大盘，`--include` 按文件名 glob 过滤（可重复），`--flatten` 只留文件名。
- 也可用环境变量代替 `--mirror-root`：`KB_MIRROR_ARCHIVE=D:\BaiduSyncdisk`。

## 已知坑（实测 2026-10-15）

1. **`/api/get` 遇非 ASCII 文件名直接断连**（服务端 bug，`kb-file/0.2`）。
   实测：`/api/get?root=archive&path=10 产品高清图/P11.jpg` → 200 / 116700 字节；
   同一目录的 `轻便侠.jpg` 或 `微信图片_*.jpg` → `curl: (52) Empty reply from server`，
   而 `/api/stat` 对同样的中文名返回正常 JSON。→ 八成是响应头 `Content-Disposition` 直接塞
   非 ASCII 文件名导致崩溃，可用 RFC 5987 `filename*=UTF-8''...` 修。
   **绕法**：`--mirror-root "D:\BaiduSyncdisk"`，中文名改走本地镜像复制（脚本仍按远端 size 校验）。
   建议把这条反馈给知识库管理员。
2. **URL 编码要按段编，斜杠保留**：`一步图片/DSC00001.JPG` → `%E4%B8%80.../DSC00001.JPG`，
   别整串 `EscapeDataString`（会把 `/` 编成 `%2F`）。官方指南第 4 节也强调这点。
3. **`files` 根没有本机镜像**：`files`（`6 产品素材` 等）里中文名文件目前只能等接口修好；
   ASCII 名（如 `DSC0xxxx.JPG`）下载正常。
4. 结果 URL / 文件的时效：知识库文件是长期存储，没有过期问题（AutoDL 侧的结果链接才是短时效）。

## 检索套路（写剧本、做设定时按这个走）

1. `kb_search`（可指定 `kb=jks-product`）拿候选 `doc_id`；
2. `kb_read` 读全文（分页 `offset` / `max_chars`），别把片段当全文；回答里带来源 `doc_id`；
3. 需要**原件**（图片/长文案）时：`kb_read` 返回的 `path` 字段往往直接给出服务端/同步盘路径，
   对照上表的镜像关系用 `kb_files.py` 取，比读库里的 OCR 摘要完整；
4. 图片类文档在库里只有「媒体条目 + OCR 索引条目」，**原图必须走 8789 或镜像盘**。
